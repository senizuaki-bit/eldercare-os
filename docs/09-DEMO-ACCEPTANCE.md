# 09 — 核心照护底座演示与验收矩阵（M00–M11）

本文件只验收第一阶段照护底座。完整内容、活动、商业和多智能体验收见 `docs/15-END-TO-END-ACCEPTANCE.md`。

## 1. 种子场景

虚构机构“青岚颐养中心”：

- 1 个组织、1 个院区、2 栋楼、4 层、若干房间床位
- 12 名虚构老人
- 8 名护工、1 名主管、1 名设备管理员
- 3 名家属账号
- 10 个设备，包括 2 个关键呼叫设备
- 一张示例 SVG 楼层图
- Fake AI、Fake Notification、IoT Simulator

禁止使用真实身份证号码、病历、头像、联系方式、录音和定位。

## 2. 主演示

1. 院长查看工作台：待复核需求、关键设备离线、超时工单和紧急事件。
2. 打开老人列表，按楼层/护理等级筛选，查看入住、授权和时间线。
3. 老人端录入：“我想喝热水，今天有点头晕。”
4. Fake transcription + structured analysis 完成；规则显示命中原因。
5. 主管复核并生成优先工单。
6. 护工收到推送、接单、查看房间位置、到场、语音完成。
7. 家属看到隐私过滤后的摘要，不看到内部备注和护工位置。
8. 老人给出评价，报表更新但不立即产生处罚。
9. IoT Simulator 停止关键设备心跳，系统创建告警、维修和替代巡查。
10. 触发紧急按钮，完成确认、响应、处置、通知和复盘。

## 3. 必测失败场景

- AI 服务超时：允许人工处理。
- 音频格式不支持：显示可理解错误。
- 设备重复 eventId：不创建重复事件。
- 位置过期：显示“位置已过期”。
- 跨机构访问：403/404 安全拒绝。
- 家属访问原始转写：拒绝并审计。
- 护工班次结束：普通访问和定位失效。
- 紧急未处理超时：升级一次且幂等。
- 网络断开：移动端保存草稿或明确失败，不假装成功。
- 同意撤回：后续 AI/位置/共享处理立即停止。

## 4. 发布候选条件

- 所有根命令通过
- 演示脚本可重复运行
- 数据库可 reset/seed
- 关键权限和状态机测试通过
- 无高危依赖漏洞或已记录例外
- 无真实密钥和真实个人数据
- README 可让新开发者启动
- 核心业务写入已经使用 outbox/幂等基础，便于 M12–M16 接入
