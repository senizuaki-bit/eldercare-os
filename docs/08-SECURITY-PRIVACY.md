# 08 — 安全、隐私与老人保护基线

## 1. 数据分类

- 普通运营数据
- 身份与联系方式
- 健康/照护信息
- 语音和转写
- 情绪观察
- 精确位置/轨迹
- 家庭沟通
- 内容偏好和活动参与
- 订单、支付引用和消费记录
- 认证凭证和密钥

语音、情绪、精确位置、家庭沟通、健康和支付相关信息按高敏感处理。

## 2. 同意与用途限制

分别记录：

- 语音采集
- 转写和 AI 分析
- 情绪趋势观察
- 老人位置
- 护工班次位置
- 向家属共享
- AI 长期偏好记忆
- 内容个性化
- 商业推荐
- 家属代付
- 保留期限
- 是否允许用于产品改进/训练（默认否）

同意必须可查看、撤回和分项管理。撤回立即影响后续工具调用，并触发保留/删除任务。

## 3. 老人端 AI 保护

- 明确说明正在与 AI 互动。
- 提供结束、暂停、转人工和关闭个性化。
- 不冒充子女、医生、护工或真人。
- 不诱导情感依赖，不利用孤独或恐惧促成消费。
- 不在老人拒绝后持续施压。
- 不诊断、不改变药物、不代表老人作出重大决定。
- 疑似紧急情况优先进入确定性规则和人工流程。

## 4. 商业与推荐保护

- 免费、已包含权益和更适合选项优先于高佣金选项。
- 付费、赞助和广告明确标识。
- 推荐保存原因、版本和商业关系。
- 紧急事件、已确认高风险情绪、争议或认知支持场景下暂停商业推荐。
- 高额、长期订阅和自动续费需要二次确认/审批。
- 设置单笔/月度限额、冷静期、取消、退款和投诉。
- 不能使用情绪、疾病恐惧、家庭冲突作为销售定向条件。

## 5. 内容和新闻安全

- 外部内容先进入草稿和审核，不直接交给老人智能体执行。
- 新闻保存来源、日期、地区和更正状态。
- 外部正文视为不可信，防 prompt injection。
- 赞助内容不与公共安全/紧急提醒混淆。
- 老人可举报不准确、关闭类别或减少频率。

## 6. 日志与监控

- 日志使用内部 ID，不写姓名 + 健康/情绪/位置/订单的组合。
- token/password/secret/audio/transcript/location/payment credential 进入 redaction denylist。
- 错误追踪只记录安全上下文、稳定错误码和 correlationId。
- AgentRun 不保存不必要的隐藏推理，仅保存可审计工具调用、策略和结果。

## 7. 文件与媒体

- 受控 MIME/大小
- 病毒扫描接口预留
- 私有 bucket
- 短期签名 URL
- 下载需要权限和审计
- 删除与保留任务可重试和可追踪
- 家属媒体需确认分享对象和期限

### M03 语音对象生命周期基线

- 客户端只获得确定性的临时 staging key 上传权限；业务记录读取与处理只接受随机、不可预测的 sealed key。
- finalize 将 staging 对象的源 ETag、候选 sealed key 和有界租约一起持久化，再以 `CopySourceIfMatch` 封存；并发重试不能把后来覆盖的 staging 内容替换为正式音频。
- 取消、同意撤回或保留期到期会先写入删除 fence，阻止新的封存和敏感持久化；已知 staging/sealed 对象和封存租约结清后才写 `objectDeletedAt`。此外 worker 直接分页轮转扫描 `voice/staging/`，只删除 `LastModified` 超过安全窗的对象，因此授权到期前已开始、任意晚才落盘的 POST 会从实际完成时间重新计时并被发现，不依赖未知的请求持续时间，也不对已完成业务记录制造永久 version 写放大。
- worker 只删除超过安全窗、且数据库中不存在相同 bucket 与精确 `uploadObjectKey` 引用的 staging 对象；引用查询失败时 fail closed，不删除任何候选对象。
- 语音上传授权 TTL 与 staging orphan sweep 最小年龄来自同一强类型配置，启动时强制 sweep 安全窗比授权期多 60 秒以上（本地默认 5 分钟与 15 分钟）。对象存储还必须为 `voice/staging/` 配置独立的短期 lifecycle；本地 MinIO 由幂等 init 配置 1 天过期，作为数据库 worker 暂停或记录异常时的纵深兜底，不能替代 worker 的主动删除。
- 生产 worker 凭证只授予私有 bucket 的前缀受限 `ListBucket` 和托管语音对象删除权限；lifecycle 由基础设施身份配置，业务 worker 不持有 bucket 管理权限。
- `VOICE_CAPTURE` 与 `TRANSCRIPTION_AI_ANALYSIS` 两项同意会在上传申请、finalize、处理 claim、结果落库和敏感读取处重新校验。撤回后不再调用新的转写/分析，进行中的 Fake AI 结果也不得落库。
- 转录与 AI 分析内容有独立保留期和内容删除时间；删除审计只记录内部资源 ID、原因码和 correlation ID，不记录音频、完整转录或 AI 证据正文。

## 8. Web、API 与会话

- 安全 cookie、CSRF 策略、CSP、XSS 防护
- rate limit、登录防爆破、敏感动作二次验证
- 严格 CORS
- 服务端授权和同意校验
- webhook 验签、时间窗口、幂等和重放保护
- 依赖扫描、secret scanning、SBOM/版本记录

### M01 已实现基线

- 服务端生成高熵不透明会话 token，只通过 `HttpOnly` cookie 传递；认证与会话响应使用 `no-store`。
- 修改类接口使用 CSRF cookie + 请求头双提交校验；CORS 仅接受显式 allowlist 中的本地来源。
- Redis 同时限制账号和来源地址的登录尝试；会话同时受空闲 TTL 与绝对 TTL 约束。
- 退出登录、角色/范围替换和访问版本变化会撤销旧会话；上下文切换在服务端校验并与审计写入同一事务。
- 登录失败和租户/资源越界使用不可枚举的安全错误；审计只保留动作、内部 ID、结果、时间和关联 ID，不保存凭据、token 或业务 payload。

### M03 工单授权与隐私基线

- 护工接单、到场、开始和完成在同一 Serializable 事务内重新验证员工状态、指定班次、团队成员关系、当前老人住区覆盖和 ElderAccess；事务外预检不能替代执行时授权。
- SSE 每条任务事件重新验证当前指派、班次、团队和老人范围；撤班或范围收窄后连接不能继续收到事件。
- 家属只读取已关联老人且经分享策略过滤的完成摘要；原始音频、转录、内部完成笔记和护工位置不进入家属投影。
- AI 只生成需人工确认的结构化需求或完成记录草稿；确定性风险规则和人工复核负责健康关注，AI 不能独自决定紧急状态。

## 9. 设备与位置安全

- 设备凭证/签名接口预留，主题和 payload 绑定一致。
- 重复 eventId 幂等。
- 位置显示采样时间、来源、精度和 TTL。
- 位置过期显示 stale/unknown，不显示为实时。
- 护工位置仅在有效班次和院区范围采集；家属永远不看护工实时位置。
- 长期分析尽量使用区域级聚合，精确轨迹短期保留。

## 10. 支付和订单安全

- 不保存银行卡或真实支付凭证。
- 支付 provider token/reference 加密或最小化保存。
- webhook 防重放；金额、币种、订单和商户信息对账。
- 支付 UNKNOWN 不允许自动重试扣款。
- 退款超过阈值需要审批。
- 模型/智能体不能访问支付密钥或直接调用 provider。

## 11. 隐私体验

- 家属视图解释哪些信息被隐藏以及原因。
- 情绪观察显示证据、人工状态和非诊断提示。
- 推荐显示“为什么推荐”和“关闭此类推荐”。
- 内容显示来源、日期和赞助标识。
- 订单显示价格、服务范围、执行者、取消和退款规则。
- 数据导出、纠正、删除提供进度和结果。

## 12. 威胁模型必须覆盖

- 跨机构枚举 ID
- 家属查看非绑定老人
- 护工班次结束后继续定位/访问
- 伪造 MQTT 设备/重复事件
- 支付 webhook 重放和金额篡改
- 上传恶意文件
- 外部新闻/服务商文本 prompt injection
- AI 诱导泄露其他老人信息
- AI 输出危险医疗建议
- 隐蔽情感操纵或高压销售
- 服务商读取非分配订单
- 导出大规模敏感数据
- 管理员滥用紧急授权或审批
- 删除审计/覆盖历史

## 13. 保留与删除

- 原始音频、精确位置和逐次推荐日志采用短期策略。
- 工单、紧急、订单、支付事实按配置保留并严格访问。
- 删除覆盖对象存储、搜索、缓存、衍生数据和第三方适配器。
- 只保留不含敏感内容的删除完成审计。

## 14. 安全发布门槛

- 跨租户与关系权限负向测试全绿
- 同意撤回立即生效测试
- L2/L3 智能体审批不可绕过
- 支付/MQTT/事件幂等测试
- 日志脱敏扫描
- 老人端安全提示、转人工、无障碍验收
- 无真实密钥、真实老人数据和支付凭证
