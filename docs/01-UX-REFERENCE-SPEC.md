# 01 — UX 视觉参考与设计规范

## 参考图用途

`docs/references/` 中的图片用于提炼：

- 后台左侧导航 + 顶部工具栏 + 内容工作区
- 卡片化运营驾驶舱
- 高密度档案表格和筛选
- 排班、房间、健康档案等业务信息组织
- 移动端白底卡片、绿色/青色点缀、大图标和底部导航

这些图片不是克隆目标。禁止复制：品牌名、logo、头像、个人信息、水印、原文案、精确页面布局和专有图标组合。

## 从参考图保留的优点

1. 信息架构清晰，管理端长期保持左侧模块导航。
2. 运营数据、档案列表、排班和房间管理适合卡片与表格混合。
3. 移动端入口直观，服务卡片和地图信息易理解。
4. 整体色彩克制，适合养老机构的可信、温和场景。

## 必须改进的地方

1. 参考图字号偏小、灰度偏低，本产品必须提高可读性。
2. 首页不能只展示装饰性图表，必须先展示风险、待处理事项、设备离线和超时任务。
3. 老人端不能像普通物业 App，要把语音、呼救、人工入口放在首屏。
4. 地图不能只展示“一个点”，必须说明位置时间、精度和是否过期。
5. 评分不能变成公开末位排名；必须展示样本量、组成和申诉/复核。
6. 情绪结果不能贴医学标签；必须显示为趋势观察和建议人工关怀。

## 设计原则

- 专业而不冰冷：医院级清晰度，社区服务级亲和力。
- 风险优先：先处理事件，再看趋势。
- 一屏一任务：老人端和护工端减少同时出现的选择。
- 状态可解释：任何风险、AI 判断、位置和分数都有原因。
- 渐进披露：家属只看到必要摘要，管理人员按权限逐层查看。
- 真实状态：所有页面必须有 loading、empty、error、offline、forbidden、stale 状态。

## 设计令牌

### 色彩

- 品牌主色：深青绿或蓝绿，用于主操作、已连接、完成状态。
- 辅助主色：稳重蓝，用于链接、信息和图表。
- 页面背景：冷灰白。
- 卡片：纯白。
- 文本：深灰蓝，不使用纯黑作为大面积正文。
- 成功：绿色；提醒：琥珀色；危险：红色；未知/离线：中性灰。
- 风险状态必须同时使用图标、标签和文字，不能只靠颜色。

建议以 CSS variables/token 实现，不把色值散落在组件里。

### 排版

- 管理端页面标题 24–28 px；区块标题 18–20 px；正文 14–16 px。
- 老人端主标题 24–30 px；正文 18–22 px；核心按钮 20–24 px。
- 表格尽量 14 px 以上，行高 48–56 px。
- 使用系统中文字体栈，不随仓库分发字体文件。

### 间距与形状

- 8 px 基础间距：8/12/16/24/32/40。
- 管理端卡片圆角 10–12 px，移动端 16–20 px。
- 阴影轻量，靠边框、留白和层级组织信息。
- 管理端内容最大宽度可流动，不固定在狭窄画布。

## 管理端全局框架

### 左侧导航

顺序建议：

1. 工作台
2. 风险与事件
3. 需求与工单
4. 老人档案
5. 房间床位
6. 护理与排班
7. 地图定位
8. 设备运维
9. 家属沟通
10. 报表绩效
11. 人员权限
12. 审计设置

左侧栏支持折叠。当前模块、未处理数量和关键离线数量可显示徽标，但避免全栏都是红点。

### 顶部栏

- 机构/院区切换
- 全局搜索
- 通知
- 当前班次/身份
- 个人菜单

### 页面结构

`面包屑 -> 标题/说明/主要操作 -> 筛选 -> 主内容 -> 详情抽屉/弹窗`

## 工作台布局

第一屏按优先级：

1. 红色紧急事件、黄色待复核、关键设备离线、超时工单
2. 今日入住/在院/床位/值班概览
3. 需求趋势、响应时间、设备可用率、服务质量
4. 公告和近期活动

不要把圆环图放在紧急队列之前。每张指标卡可点击进入已过滤列表。

## 表格与档案

档案列表支持：

- 姓名/床位/护理等级/状态搜索
- 机构、楼栋、楼层、照护组筛选
- 保存筛选视图
- 列显示设置
- 批量操作（权限控制）
- CSV 导出（审计）
- 详情使用侧边抽屉，编辑进入独立页面或分步表单

健康与照护档案采用标签页：基本信息、护理计划、过敏/禁忌、药物计划、需求事件、服务记录、同意与共享、审计。

## 地图与位置

- 使用上传的 SVG/PNG 楼层图。
- 图标区分老人、护工、设备、事件。
- 每个位置显示采样时间、来源和精度。
- 超过 TTL 后变灰并标注“位置已过期”。
- 紧急模式突出事件位置、最近可用护工、路线/房间说明和响应计时。
- 常规模式不得制造“所有人被持续监控”的观感。

## 移动端：老人模式

首屏只保留：

- 大号“按住说需求”/“点击说需求”按钮
- 一键紧急求助
- 今日安排和用药提醒（只提醒，不给医疗建议）
- 联系家属/联系人工
- 最近服务和评价

每次 AI 对话明确显示“AI 关怀助手”，提供结束和转人工。老人可以拒绝分析或撤回共享授权。

## 移动端：护工模式

首屏：

- 当前紧急任务
- 我的待办
- 附近/同楼层任务
- 今日班次
- 交班提醒

任务详情：老人称呼、房间/区域、需求摘要、风险原因、注意事项、计时、接单/到达/处理/语音完成。避免展示无关病史。

## 移动端：家属模式

首屏：

- 今日状态摘要
- 未读事件/需要家属参与
- 服务进度
- 最近趋势
- 沟通助手草稿

不显示原始录音、完整对话、护工实时位置和内部备注。


## 移动端：内容、活动与服务

- 新闻/内容卡必须显示来源、日期和类型；赞助内容显示清晰标签。
- 老人端不使用无限滚动商业信息流，默认采用“今日精选 + 主动搜索 + 已订阅权益”。
- 活动卡显示时间、地点、是否需要陪同、费用、剩余名额和推荐原因。
- 服务卡显示价格、包含内容、执行者类型、取消/退款规则和是否已包含在服务包。
- 商业推荐暂停时不留空白诱导，显示“当前优先处理照护事项”。
- 高额或长期服务确认页使用分步确认，不使用预勾选自动续费。

## 多智能体体验

- 对外保持一个统一 AI 入口，不让老人理解复杂的智能体名称。
- 界面可以解释“正在为您查询活动/联系护工/准备沟通建议”，但不能伪装业务已完成。
- 工具执行状态区分：准备中、需要确认、已提交、执行失败、转人工。
- 涉及 L2/L3 动作必须显示确认对象、影响、价格/共享范围和可撤回方式。
- 管理端 Agent Run 详情显示工具调用、审批和最终业务对象，不展示无必要的隐藏推理。

## 可访问性验收

- 键盘可操作管理端关键流程。
- 屏幕阅读器能读出标签、状态和错误。
- 老人端核心按钮不少于 56×56 px。
- 不用 placeholder 代替 label。
- 表单错误靠文字说明，不只红框。
- 动画可关闭。
